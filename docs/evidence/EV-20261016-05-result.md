# EV-20261016-05 Windows 良性経路計測

2026-10-16、[事前固定した評価 identity](../evaluation-manifests/EV-20261016-05.json) に従い、Windows loopback の同じ `/home` 応答を direct backend と router 経由で 400 組測定した。順序は交互、各 origin の warmup は 1 回。モデル呼出しなし。計測 runner の wall-clock `perf_counter_ns` には TCP 接続、HTTP 応答、body 読取を含む。

| 指標 | 結果 | 暫定基準 |
|---|---:|---:|
| 追加遅延の組差 p95 | 38.59 ms | ≤30 ms：**未達** |
| direct p95 / router p95 | 25.15 / 46.10 ms | 参考値 |
| 良性誤誘導 | 0/400 | <1% |
| route event 記録 | 400/400 | ≥99% |
| 応答の status/body 不一致 | 0/400 | 0 |

良性誤誘導 0/400 の Wilson 95% 上限は約 0.95%、記録率 400/400 の下限は約 99.05%。このローカル試行では副指標は基準を満たした。遅延の中央値差は 15.78 ms、p95 差は 38.59 ms。direct も p95 25.15 ms と遅く、Windows の loopback/スケジューリングと、router の都度発生する upstream 接続・SQLite event 書込が候補要因。内訳を分離測定していないため、実装の非効率と断定しない。比較可能な過去の成功実行や文書化された期待時間はなく、所要時間の基準は不明。Linux の対象条件で再測定するまで NFR-A は不合格として扱う。

[生の400組測定値](EV-20261016-05-benign.json) の SHA-256 は manifest へ固定した。postrun checker の成功は測定の同一性確認であり、30 ms ゲートの合格を意味しない。
